# چک‌لیست تست روی گوشی — موتور گفتار آفلاین شنوا

این صفحه فقط برای یک کار است: تأیید اینکه تشخیص گفتار آفلاین روی **گوشی واقعی** کار می‌کند و زمانش قابل قبول است. لپ‌تاپ/دسکتاپ معیار نیست.

## آدرس‌هایی که باید باز کنید

| چه چیزی | آدرس |
| --- | --- |
| صفحهٔ تشخیص (اول این) | `https://<your-domain>/test-shenava.html` |
| صفحهٔ Preview همین شاخه | `https://billora-git-arena-d9de851e-billora-ai-image-app.vercel.app/test-shenava.html` |
| Production | `https://billora-ai-image-app.vercel.app/test-shenava.html` |
| فرم فاکتور (تست نهایی) | `https://<your-domain>/` |

> دامنه‌های ورسل این پروژه پشت **Vercel Authentication** هستند. اگر صفحهٔ ورود Vercel آمد، اول در همان مرورگر گوشی به حساب Vercel خودتان وارد شوید (یک‌بار) و بعد آدرس را باز کنید. اگر می‌خواهید بدون ورود هم باز شود و بشود با `curl` تأیید کرد، در Vercel → Settings → Deployment Protection گزینهٔ Vercel Authentication را برای Production خاموش کنید.

## گام‌به‌گام

### ۱) صفحهٔ تشخیص را باز کنید و وضعیت را بخوانید
باید این‌ها را ببینید:
- **موجود بودن مدل:** «موجود»
- **منبع مدل:** «کنار خود برنامه» (اگر روی Preview/Production باشد) — نشانهٔ اینکه فایل‌ها از همان دامنه می‌آیند.
- **جدول فایل‌ها:** هر چهار فایل با حجم درست. اگر انکودر بزرگ باشد، در ستون «تکه‌ها» می‌بینید: `2 تکه (جمع 125.3 MB) encoder.int8.onnx.part0` — یعنی فایل بزرگ زیر سقف ۱۰۰ مگابایتی ورسل دو تکه شده و مرورگر آن را از همان دامنه می‌گیرد.
- **Cross-Origin Isolated:** «بله (چندرشته‌ای)». اگر «خیر» بود، هدرهای COOP/COEP روی آن دامنه نیستند و موتور تک‌رشته‌ای (کندتر) اجرا می‌شود.
- **موتور فعال:** «شنوا آفلاین» یا «Web Speech مرورگر» — همراه **دلیل** انتخاب
- **شکل تنسورهای RNNT:** ردیفی که شکل‌های واقعی مدل را نشان می‌دهد؛ برای این مدل باید شبیه این باشد:
  `predictor states context=1(shape) targets=int32[1,1] states=[1,1,640][1,1,640] · joiner encoder_outputs[1,512,1] decoder_outputs[1,640,1]`
  اگر این ردیف `—` بود، یعنی صفحه هنوز از نسخهٔ قدیمی استفاده می‌کند (شاخه را دوباره deploy کنید).
- **iOS-like / Android:** باید سیستم گوشی شما را درست نشان دهد.
- اگر چیزی «ناقص» بود، نام فایل ناموجود در پیام آمده است؛ همان را گزارش کنید.

### ۲) تست میکروفن (روی همان صفحه)
1. «شروع ضبط» → اجازهٔ میکروفن را بدهید.
2. واضح بگویید: **«سلام حال شما خوبه»**
3. «توقف و تبدیل» را بزنید.
4. باید همین جمله با املای فارسی در کادر بیاید.
5. زمان‌ها را از بخش «زمان هر مرحله» بخوانید: `ویژگی (log-mel)`، `انکودر`، `دیکود RNNT`، `کل زمان`.
   - معیار قبولی: **کل زمان کمتر از ۳ ثانیه** روی iPhone 12 و بالاتر یا گوشی هم‌رده.
6. دو بار تکرار کنید (بار اول ممکن است کندتر باشد، چون مدل در حال کش شدن است).
7. اگر خطایی دیدید (مثلاً پیام `OrtRun` یا شکست تشخیص)، لطفاً کنسول مرورگر را هم باز کنید و خطوطی که با
   `[shenava]` شروع می‌شوند را بفرستید؛ آن‌ها امضای ورودی/خروجی مدل و شکل تنسورهایی که فرستاده می‌شود را
   نشان می‌دهند (روی iPhone: Settings → Safari → Advanced → Web Inspector، یا روی Android Chrome با
   `chrome://inspect`).

### ۳) تست آفلاین
1. اینترنت را قطع کنید (حالت پرواز).
2. صفحه را **رفرش** کنید و مرحلهٔ ۲ را دوباره انجام دهید.
3. اگر جمله درست آمد، موتور کاملاً آفلاین روی دستگاه کار می‌کند. اگر نشد، همین را گزارش کنید (یعنی کش مدل کامل نشده).

### ۴) تست اصلی: تشخیص گفتار در فرم فاکتور
1. به صفحهٔ اصلی/فاکتور برو
2. روی میکروفن بزنید و بگویید: **«دو عدد برنج هاشمی اضافه کن»**
3. باید:
   - متن داخل **همان ورودی فرمان** بیاید (نه اینکه فاکتور خودکار عوض شود)،
   - دکمهٔ «اجرای دستور» دست‌نخورده بماند،
   - ردیف‌های موجود فاکتور هیچ تغییری نکنند،
   - اگر روی «اجرای دستور» زدید، فرمان مثل قبل (بدون تغییر) اجرا شود.
4. ورودی متنی و دکمهٔ «اجرای دستور» باید در همهٔ حالت‌ها (حتی وقتی موتور گفتار غیرفعال است) کار کنند.

### ۵) اگر می‌خواهید خروجی ماشینی بگیرید (اختیاری، از رایانه)
روی هر ماشینی که Node دارد و به اینترنت وصل است:

```bash
npm run verify:deployed -- https://<your-domain>
```

این ابزار همان چیزی را انجام می‌دهد که `curl -I` انجام می‌دهد: برای هر فایل مدل، صفحهٔ تشخیص، و هدرهای COOP/COEP یک حکم PASS/FAIL می‌دهد و کد خروج ۰/۱ برمی‌گرداند. اگر دامنه پشت Vercel Authentication باشد، این ابزار هم پاسخ `302` می‌گیرد و همین را گزارش می‌کند (یعنی «به‌خاطر محدودیت دسترسی، از بیرون قابل اندازه‌گیری نیست» — نه اینکه فایل‌ها نیستند).

## چه چیزی را برای من بفرستید

1. مدل گوشی و نسخهٔ سیستم (مثلاً `iPhone 12 · iOS 18.4` یا `Galaxy A54 · Android 15`).
2. جمله‌ای که تشخیص داده شد (درست یا غلط).
3. زمان `کل زمان` برای آن جملهٔ ۵ کلمه‌ای.
4. نتیجهٔ تست حالت پرواز (کار کرد / نکرد).
5. هر پیام خطا یا عددی که در صفحهٔ تشخیص دیدید (مثلاً «ناقص: …» یا `threads`).
